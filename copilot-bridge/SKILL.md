# Copilot Bridge

Setup this solves: the strong unlimited model (Copilot GPT on the Windows host) can't
see the repo; the agent that CAN see the repo (Windsurf on the Linux VM) is weak and
credit-limited. Naive bridging — pasting thousands of raw lines per chat — drowns the
strong model in noise and can't be kept current.

Two principles: (1) **maintain documents, not conversations** — chats have no memory
and degrade as they grow; keep a curated context pack updated and start fresh sessions
from it; (2) **distill, don't dump** — a 200-line map outperforms 3,000 raw lines;
raw code goes in only for the files under discussion.

## When this triggers

- Starting or preparing any session with the chat-only strong model (planning, design
  options, explaining code, diff review, distilling long reports).
- The context pack needs regenerating or the standing documents need bootstrapping.
- The user invokes `/copilot-bridge`.

## When this does not trigger

- The paid in-repo generation itself → `token-sniper` (this skill's handoff prompt
  feeds it).
- Sessions with home Claude — no pack needed there, and work code never goes there.
- Verification of a finished diff before commit → `explain-before-merge` (the bridge's
  diff review is a *pre*-check, not the gate).

## Required inputs

- The work repo path (where `.agent/` lives) and the files under discussion.
- The standing documents: `.agent/PROJECT-BRIEF.md` (bootstrap it once if missing —
  paste the repo tree into Copilot, co-write one page), the current feature brief,
  the latest impl-log.
- One-time: confirmation the Copilot is the enterprise/work-account variant before any
  source code is pasted.

## Workflow

1. **Generate the pack** (zero credits): `scripts/context-pack.sh <relevant files>` →
   `.agent/context-pack.md`: project brief → current task brief → latest impl-log →
   uncommitted diff (truncated) → the named files, fenced and labeled, with a token
   estimate and bloat warning.
2. **Fresh chat, always.** Open with the session-opener prompt from
   `assets/copilot-session-prompts.md` — it makes the model treat the pack as source
   of truth, state its understanding in 3 sentences, and list what's missing. Fix gaps
   before the real question; a model that starts wrong stays wrong.
3. **Work the question:** planning, design options, explain-this-code, diff review,
   report distillation — prompts for each in the assets file.
4. **End with the handoff:** have the strong model draft the token-sniper one-shot
   prompt for Windsurf (prompt #5). The strong model plans; the weak model only types.
5. **Persist what matters:** durable decisions → impl-log; domain explanations →
   knowledge note. The chat itself is disposable.

## Decision gates

- No source code into a Copilot that isn't confirmed enterprise/work-account.
- Fresh chat per task or per day, whichever comes first — if the model gets confused,
  regenerate the pack and restart rather than arguing.
- Packs stay under ~30k tokens; past that, trim the file list (never the standing
  documents).
- The trust ladder still applies: GPT is stronger, not omniscient — claims about the
  codebase need the one-hop verification; it only knows what the pack shows it.

## Output format

Per session: the generated pack path + the ready-to-paste opener; at session end, the
drafted Windsurf handoff prompt and a note of what was persisted to the impl-log or
knowledge notes.

## Gotchas

- Trying to keep one long-running chat "updated" is unwinnable — the pack is the
  memory, the chat is disposable.
- Don't paste raw agent reports; distill them first (prompt #6) and reuse the
  distillation in future packs.
- The paper trail (briefs, logs, decision records) IS the bridge's memory — a system
  that lapses there starves the pack.

## Division of labor (the full triangle)

**Copilot GPT (unlimited, no repo):** planning, architecture options, explaining
pasted code, reviewing diffs before `explain-before-merge`, distilling reports,
drafting Windsurf prompts, rehearsing review-defense answers. **Windsurf (repo,
credits):** executing prepared prompts only. **Claude home (no work code, ever):**
domain concepts abstractly, skill/workflow maintenance, career strategy.

## Evaluation checklist

- [ ] Pack generated by the script (not hand-pasted raw code) and under the size warning?
- [ ] Fresh chat opened with the session-opener; model's 3-sentence understanding checked?
- [ ] Session ended with a drafted handoff prompt (when generation is next)?
- [ ] Durable outputs persisted to impl-log / knowledge notes?

## Assets

- `assets/copilot-session-prompts.md` — the six prompts: opener, planning, explain,
  diff review, handoff, distillation.

## Scripts

- `scripts/context-pack.sh` — builds `.agent/context-pack.md` from the standing
  documents + named files; prints a token estimate; `--no-diff` to skip the diff section.
