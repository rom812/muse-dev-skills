# /stuck — Stuck Protocol

1. Ask me: what am I trying to make happen, in one sentence? If I can't say it, the
   real gap is understanding → route me to /brief (requirements) or /tutor (domain).
2. Ask me to name the next 30-minute-sized subtask. If I can name it → maybe I'm not
   stuck, just overwhelmed; start there and stop this workflow.
3. Start a stuck log (scratch note): goal / attempts → results (exact errors) /
   ruled out. Set a 30-minute timebox (2h total ceiling for multi-day tasks).
4. Free sweep before any paid AI generation: grep the repo for a precedent, search the
   wiki MCP, check .agent/knowledge/ notes, and Exa-search the exact error message in
   quotes (someone wrote the blog post that solves it). If an AI explanation of the
   codebase is involved, verify one hop (open the actual method) before trusting it.
5. Timebox expired? Compose the ask from the stuck log:
   "I'm trying to [goal]. I tried [A] → [result], [B] → [result]. My best guess is [C]
   because [reasoning]. Am I on the right track?"
   Best-guess line is mandatory. Suggest whether it goes to my safe person, my
   question-slot batch, or immediately to my boss (blocking + deadline = immediately).
6. When the answer comes: record it in the parking-lot note or promote to /tutor;
   log the ask in the impl-log (/log). Asking after a documented timebox is discipline,
   not weakness — sitting silent past 2× the timebox is the actual failure mode.
